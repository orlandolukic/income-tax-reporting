# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Start of every session

1. Read `DEVLOG.md` first to restore context: completed work, recent changes, open tasks.
2. Read `README.md` for setup and run commands if needed.

## Project rules

1. **Architecture:** client-server. The backend exposes an HTTP API under `/api`; the frontend consumes it. Keep business logic on the backend.
2. **Technologies:** backend in Python (FastAPI), frontend in React with TypeScript (Vite). Do not introduce other languages or frameworks without asking.
3. **Development log:** keep `DEVLOG.md` up to date. At the end of each piece of work, add a dated session entry with:
   - **Completed**: what was done and verified
   - **Changes**: notable modifications to existing code or structure
   - **Open / next tasks**: unfinished work and known issues
4. **UI language (user's rule, 2026-11-13):** two languages, each for its kind of text, in every page, component and backend message:
   - **English: everything passive.** Navigation and sidebar, page / card / section titles, button, tab and field labels, placeholders, column headers added by the app, badges and counters ("165 companies", "Selected 5 of 165"), aria labels.
   - **Serbian (Latin, with č ć đ š ž): every message addressed to the user**, so it is understood well: errors and warnings, success / info alerts, confirmation questions and their explanation, save status, loading text ("Učitavanje…"), empty states, validation messages, explanatory tooltips, page / card descriptions (sentences under a title), and every backend message the UI can show (`HTTPException` / service error `detail`).
   - Data is never translated: Excel column headers, PB-1 texts and sheet names, company names.
   - **No UI text or message mentions Excel** (user's rule, 2026-11-14): e.g. "Izmenjeno. Prvobitna vrednost: …", "Prazno (samo za čitanje)", "Uvezene godine …", "Godina … je uvezena; …". The source file names (e.g. "2025 GFI TOKK 1.xlsx", "2025 PB-1.xls") are not shown anywhere either (user, 2026-11-14): Home / Edit Company Data show "<n> companies", Migration shows "imported" / "constructed from <year>" and "PB-1 form" / "no PB-1 form"; the PB-1 page has no values badge any more ("Imported values" / "N values entered" / "No PB-1 values yet" removed, user 2026-11-17). The API still returns them (internal).
   - Code, comments, logs and docs stay English.
5. **Application logging:** use the project loggers with levels DEBUG, INFO, WARNING, ERROR, CRITICAL. Do not use bare `print` or `console.log`.
   - Backend: `from app.logging_config import get_logger; logger = get_logger(__name__)`. Level is set by `LOG_LEVEL`; output goes to the console and `backend/logs/app.log`.
   - Frontend: `import { getLogger } from "./logger"; const logger = getLogger("Name");`. Level is set by `VITE_LOG_LEVEL`; output goes to the browser console.

The application is named **Income Tax Reporting** (FastAPI title, sidebar, Login page, browser tab title; npm package `income-tax-reporting-frontend`).

## Commands

- Backend dev server (from `backend/`): `.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000`
- Frontend dev server (from `frontend/`): `npm run dev`
- Frontend type check (from `frontend/`): `npx tsc -p .`
- App: http://localhost:5173; API docs: http://localhost:8000/docs
- Database schema (from `backend/`, needs `DATABASE_URL`): `.venv\Scripts\alembic upgrade head`. After changing `app/models.py`, create a migration with `.venv\Scripts\alembic revision --autogenerate -m "..."`, review it, and check with `.venv\Scripts\alembic check`.
- GFI import (from `backend/`): `.venv\Scripts\python -m app.gfi_import <year> --dry-run`, then without `--dry-run`. Use `--replace` to import a year again.
- PB-1 import (after the year's GFI import): `.venv\Scripts\python -m app.pb1_import <year> --dry-run`, then without `--dry-run` (`--replace` only while no PB-1 edit is stored).

## Data rules

- GFI workbooks (`<year> GFI *.xlsx` in `GFI_DATA_DIR`, default the project root) are **read-only**. Never write to them.
- **Migracija** (`app/migration.py`, page `/migration`, sidebar "Administration" → "Migration"): the next year (latest + 1) is constructed from the latest year with the companies chosen in a dialog (registry of all companies).
  - **A constructed year behaves exactly like the year it is built from** (user's rule, 2026-11-13). It is built as a copy of the source year (each company's original cells with their kinds, formats, formula flags; columns; the PB-1 form and its settings), then only the agreed changes are applied: NAZIV, PIB, REFERENT, office = current values (an unchanged one is the source cell copied as it is, e.g. a PIB stored as a number); status columns that hold a number become 0, empty ones stay empty (so Home edits exactly the same cells); company values and PB-1 amounts are not carried. Never re-create cells or settings from scratch.
  - **Everything added later** (tables, settings, flags) applies to imported and constructed years alike and must be carried by the next construction the way it is in the current state; a constructed year is the base for the next one. Every table needs a policy in `YEAR_TABLES` / `GLOBAL_TABLES` in `app/migration.py` (construct + delete); the backend refuses to start while a table has none (`check_table_policies`).
  - After a change to construction: construct on a scratch copy and compare the new year with its source cell by cell through the API (only status numbers → 0 may differ), and run construct → delete (database identical). Constructed years: `source_file.origin = 'constructed'`; a deselected company is hidden (`company_year.active = false`), never deleted. The year then appears in the Reporting year selector; the selector itself never offers to add a year. Construction also creates the year's PB-1 form (`ensure_pb1_form`: a constructed 'pb1' source_file): the same three tabs as the source year's form as shown in the app (its form-level settings copied: shared template edits; the comments are global), all amounts 0, no file values for anyone, years in read-only texts moved on (`form_source` in `app/pb1_store.py`, `shift_years`). Everything from the database (`copy_form_settings`); no file is read. **Deleting a year** (user's rule): only the latest year, and only if it was constructed (a wrong construction is undone; a workbook year is never deleted here). A red "Delete…" button only on that year's row, then a confirmation dialog (`AlertDialog`); `DELETE /api/migration/years/{year}` (`delete_year`) removes its company years, cells, its PB-1 form with all values and template edits (the global comments stay), the PB-1 link and the year, its `change_log` history, plus companies / referents / offices no year uses any more; the shared company details (`company.name`, `company.pib`, shared by all years) that the year's edits changed are restored from `change_log` (`_undo_shared_details`: the last change made in another year, else the value before the first change). Nothing of the year is left and nothing of the other years changes (user's rule; verified by comparing every table before construction and after deletion).
- **PostgreSQL is the only data store** (PostgreSQL 18, SQLAlchemy 2.1, psycopg 3, Alembic). `DATABASE_URL` (`backend/.env`) is required: without it the backend doesn't start (CRITICAL in the log). **Active since 2026-11-12** (database `income_tax_reporting`, 2025 imported). **Since 2026-11-13 everything is in it** (user's rule: from the introduction of PostgreSQL there is no more contact with the Excel files): GFI data, the PB-1 forms (snapshot of the workbook), all PB-1 edits, company values, the global comments, the PB-1 link, users and sessions. The app never opens an Excel file: only the one-time imports (`gfi_import`, `pb1_import`) read them, when the user asks for it. The app's modules don't even load the Excel libraries (`openpyxl` only in `app/gfi_workbook.py`, `xlrd` only in `app/pb1_file.py`, both imported only by the imports). New data must go into PostgreSQL too (no files, no SQLite).
  - The user installs PostgreSQL themselves when it is needed. Do not install it.
  - **There is no Excel / SQLite mode any more** (removed 2026-11-13 at the user's request). The old SQLite store (`backend/data/edits.db`) was checked row by row against PostgreSQL (59 rows, all present) and deleted on 2026-11-13. Anything the app must remember goes into PostgreSQL through a model in `app/models.py` and an Alembic migration; no files, SQLite or other stores (`app/db.py` accepts only a PostgreSQL URL).
  - Data gets into PostgreSQL only through the imports (then through the app). `app/gfi_import.py` keeps only the company list (rows while R.B. continues 1, 2, 3, …; 2025: 165 companies up to DAGOTTA) and verifies every cell against the workbook before committing. `app/pb1_import.py` stores every cell of the PB-1 sheets (value, format, bold, fill, used range, column widths), fills the global comments from the workbook (only rows without one; never overwrites), and commits only if every company's PB-1 tables (all years using the form, all tabs) are equal with the form read from the file and from the database. Neither writes the Excel file.
  - Referents and offices are lookups: a name no company uses any more is removed when a company's referent / office changes (`_drop_if_unused` in `app/gfi_store.py`).
  - Before deleting or replacing database records, check that no user edits are lost. `--replace` refuses while any value differs from the import snapshot; `change_log` history is always kept.
  - Schema: `reporting_year`, `source_file` + `gfi_column` + `source_cell` (read-only snapshot of the original cells: values, formats, formula flags), `company`, `company_year` (current values, addressed by Excel row `source_row`), `referent`, `office`, `import_issue`, `change_log`; PB-1: `pb1_sheet` + `pb1_sheet_column` + `pb1_source_cell` (read-only workbook snapshot, under a 'pb1' `source_file`), `pb1_template_edit` (per year, shared by every company), `pb1_company_edit` (per `company_year`: amounts, months; RESTRICT, so a company year with PB-1 values can't be deleted), `pb1_comment` (global: one per form row for every year and company, migration 0014), `pb1_link`; `app_user`, `user_session` (SHA-256 of the token). ## Design guidelines

The permanent visual style is modeled on **Shadcn Admin** (https://github.com/satnaing/shadcn-admin). Every new page and component must follow it.

**Stack**
- Tailwind CSS v4 (via `@tailwindcss/vite`) and **shadcn/ui**, style `new-york`, base color `neutral` (see `frontend/components.json`). Radix primitives come from the `radix-ui` package.
- Icons: `lucide-react` only. Font: Inter (`@fontsource-variable/inter`).
- React 19 (needed so shadcn components forward refs correctly).
- Import paths use the `@/` alias for `src/` (for example `@/components/ui/button`).

**Components**
- Build UI from shadcn components in `src/components/ui/`. If one is missing, add it with `npx shadcn@latest add <name>` (from `frontend/`). Do not hand-roll an equivalent.
- After adding a component, check its imports. The CLI has written `from "cn"` instead of `from "@/lib/utils"` and installed an unrelated `cn` npm package. Fix the imports and uninstall that package if it appears.
- Treat `src/components/ui/` as vendored: avoid editing these files. Customize through `className` at the call site.
- Merge classes with `cn()` from `@/lib/utils`.

**Colors and theming**
- Use only the semantic theme tokens (`bg-background`, `text-foreground`, `bg-card`, `text-muted-foreground`, `bg-primary`, `text-destructive`, `border`, `bg-sidebar`, ...). They are defined in `src/index.css` for light and dark.
- Never hard-code colors (no hex values, no `text-gray-500`, no inline `style` colors). Every UI must work in both light and dark.
- **App mark** (user, 2026-11-17): `AppLogo` (`src/components/AppLogo.tsx`): lucide Landmark on a blue tile, white columns, golden roof; tokens `--brand`, `--brand-foreground`, `--brand-accent` (light and dark in `src/index.css`). Used in the sidebar and on Login; the browser tab icon is the same mark in `public/favicon.svg` (hex colors there, it is a static file).
- Accent colors: `chart-1`, `chart-2`, `chart-3` (shadcn chart palette, defined for light and dark in `src/index.css`), e.g. tinted buttons `border-chart-1/40 bg-chart-1/10 text-chart-1`.
- Status colors: `text-success` (green, token `--success`, light and dark in `src/index.css`) and `text-destructive` (red). Home colors the 0 / 1 values of Preliminarni … PB-1,PB-2 za rad: 1 green, 0 red (`statusColors` in `CompanyTable`).
- Theme: `ThemeProvider` (`src/context/ThemeProvider.tsx`) has **two themes only: light and dark** (user's rule, 2026-11-15; no "system" option), saved in `localStorage` (`ui-theme`); until the user chooses one, the operating system's preference is used when the page loads. It toggles the `.dark` class on `<html>`. Users switch it with `ThemeSwitch` in the header.

**Layout**
- Logged-in pages render inside `AuthenticatedLayout` (`src/components/layout/`). It contains a collapsible floating `AppSidebar` (logo, nav groups, user menu with Log out), a sticky `Header` (sidebar toggle, theme switch, profile menu) and the routed page.
- A new page is a route nested under the `AuthenticatedLayout` route in `App.tsx`. Wrap its content in `<Main>`, and add a sidebar entry in `src/config/navigation.ts` (title, url, lucide icon).
- Page header pattern: `<h1 className="text-2xl font-bold tracking-tight">Title</h1>`, with an optional `<p className="text-muted-foreground">` description below.
- Public/auth pages (such as Login): a centered `max-w-sm` column on `bg-muted/40`, with the logo above a `Card`.

**Patterns**
- **Search field in the header** (user, 2026-11-17): a page that needs a search renders `<HeaderSearch>` (`src/components/HeaderSearch.tsx`); it appears at the top right of the sticky page header (slot left of the theme switch), so it is always in sight however far the page is scrolled. Matching is case- and diacritic-insensitive (`searchText` / `matches` in `src/lib/search.ts`; đ = dj). Used on Home and Edit Company Data ("Search companies": filters by NAZIV, PIB, REFERENT, office; `#` keeps the list position; "x of N companies"; Serbian empty message) and on PB-1 Poreski bilans only ("Search the form": marks the rows whose #, Opis or Konto match, form and closing rows, light amber, the focused one stronger, scrolled to the middle; "2 / 17", Enter / Shift+Enter and arrows; Escape clears). Not on the other two PB-1 tabs.
- **Cursor (user's rule):** everything clickable shows the pointing hand (`cursor: pointer`), never the default arrow: buttons, tabs, checkboxes, selects, menu and list items, links, labels, and table cells / comments that open an editor on click (`cursor-pointer` while not editing). The global rules are in `src/index.css` (base layer + menu/select items); new clickable elements that are not buttons or links get `cursor-pointer`. Non-clickable things keep the arrow; disabled controls keep `cursor-not-allowed`; text inputs the text cursor; resize handles their resize cursor.
- Forms: `Label` + `Input` pairs in `grid gap-2`; fields in `grid gap-4`; a full-width primary `Button` with a `Loader2 animate-spin` icon while submitting.
- Errors: `Alert variant="destructive"` for form or page errors, and `aria-invalid` on invalid inputs.
- Spacing and shape: Tailwind spacing scale (`gap-2/4/6`, `p-4`, `px-4 py-6`), radius tokens (`rounded-md`, `rounded-lg`), and subtle borders. Keep it minimal and clean, without decorative gradients or heavy shadows.
- Responsive: layouts must work at mobile width (the sidebar becomes a sheet below `md`).
- Data tables: follow `src/components/CompanyTable.tsx`.
  - Use one `overflow-auto rounded-md border` scroll container with a max height, and a raw `<table>` with shadcn `TableHeader/TableRow/TableHead/TableCell`. Don't use the `Table` wrapper, because its own scroll box breaks sticky headers.
  - Header row: sticky `bg-muted`. Row numbers: a sticky left column.
  - Numbers: `text-end tabular-nums`.
  - Cells: `hover:bg-accent` with an enlarged hover preview of the full value.
  - `SidebarInset` has `min-w-0`, so wide content scrolls inside the page instead of widening it.
